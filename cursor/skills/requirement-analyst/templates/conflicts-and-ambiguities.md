# Conflicts and Ambiguities

Single source of truth for unresolved conflicts and ambiguities found during requirement analysis. Use one row per issue.

Conflict and ambiguity rows use the same format.
When an issue is resolved, remove it from this table.
Keep each row atomic. If multiple issues have different affected items, sources, or severities, split them.

```markdown
| ID | Description | Source | Severity |
|----|-------------|--------|----------|
| CA-NNN | [One sentence naming what conflicts or is ambiguous, including affected item IDs such as REQ-NNN, QR-NNN, ASS-NNN, CON-NNN, INV-NNN, POL-NNN, or Q-NNN.] | [Source artifact and reference] | blocking \| risky \| informational |
```
